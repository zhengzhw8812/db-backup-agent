# v3.1 备份可信批次设计(云端保留 / 备份验证 / 看门狗 / 安全与前端小项)

- **日期**: 2026-10-01
- **状态**: 待审阅
- **定位假设**: 纯自用、稳定性优先(用户定位问题的默认项,可随时推翻)

## 1. 背景

v3 重构清理收尾完成后(185 测试全绿、E2E 13 步通过、CI 上线),代码审查与事实核实确认了四个真实缺口:

1. **云端副本只增不减**:保留清理(`retention.py`)与手动删除(`DELETE /backups/{id}`)均只删本地;上传到 S3 兼容存储的副本永久残留(含过期数据库数据);
2. **备份从不被验证**:checksum 写入记录后没有任何机制复核,gzip 损坏、磁盘位翻转、云传输截断都无人知晓;
3. **备份没跑无人知**:容器重启后 APScheduler 状态丢失、cron 异常、调度器死亡都只体现在"该来的备份没来",无主动告警;
4. **传输与暴露面**:`/docs`(Swagger)默认对所有访问者开启;静态资源无压缩(Dashboard 单 chunk 500KB,整包 1.4MB);无 404 页;状态标签渲染函数在 3 个 view 中逐字重复。

## 2. 目标

过期数据不留在云端、坏备份能被发现、没跑的备份有人报警、传输体积与暴露面收紧。全部行为向后兼容,既有 185 项测试不改断言全绿。

### 非目标

- 不更换前端技术栈(Vue 3 + Naive UI 即正确答案);i18n、多用户/2FA 回归、增量备份、新通知渠道(Telegram/钉钉等)均不做;
- 不做备份内容级校验(如导入 dump 试连数据库)——文件级验证(gzip CRC + checksum 复核)已覆盖主要风险,内容级验证列为未来选项;
- 不补"云目标已删除导致的孤儿副本"清理(目标都没了无从谈起),文档记为已知限制。

## 3. 云端保留策略

**删除联动两条路径**:

- `run_retention(db, conn, backup_dir)` 删除每条过期记录前,取 `rec.file_path` 作为对象 key,对该连接**所有启用的 SyncTarget**对应目标执行 `storage.delete(cfg, key)`;
- `DELETE /backups/{record_id}` 同样联动(仅在 `rec.file_path` 存在时)。

**语义与容错**:

- 单个目标删除失败:记 SystemLog(source=`retention`/`backups`,level=warning,含目标名与 key),继续处理其余目标与本地删除,不阻塞、不回滚(与通知同原则);
- 目标/目的地已被删除:跳过该目标(孤儿副本为已知限制);
- 云删除在本地文件删除**之前**执行(云端失败时本地记录仍在,用户可在 UI 重试删除;反之先删本地会留下无法追溯的云副本);
- SyncTarget 无启用目标 → 直接跳过,零开销。

**测试**:每条路径两个用例(联动成功删云副本;云删除失败不阻塞且记日志)。

## 4. 备份验证

**Schema**(`backup_records` 补列,走 `maintenance._ensure_column` 既有机制):
`verify_status TEXT NULL`(passed/failed)、`verified_at DATETIME NULL`、`verify_error TEXT NULL`。

**验证逻辑**(`app/services/verify_service.py` 新建):
1. 解析 `backup_dir / rec.file_path`(路径穿越校验沿用 sync_service 的写法);
2. **单次读 .gz 文件**:逐块更新 SHA-256(与 `rec.checksum` 比对——注意现有 `compress_and_hash` 的 checksum 是**压缩字节**的哈希,故直接哈希 .gz 文件内容),同时把同一批字节喂给 gzip 解压器流式验证 CRC 与完整性(不落盘、常量内存);
3. 通过 → `verify_status=passed, verified_at=now`;失败(gzip CRC 损坏 / checksum 不符 / 文件缺失 / 路径非法)→ `failed` + `verify_error`(异常摘要)。

**手动验证**:`POST /api/v1/backups/{record_id}/verify` → 仅接受 `status="success"` 且有文件的记录(否则 409);复用 arq:`verify_job(record_id)`(`workers/app.py` functions 注册;job 内再校验一次,记录缺失或 running 则直接跳过),进度简单(两阶段:解压/比对),复用 ProgressReporter(kind="job",频道复用 record_id)前端 SSE 可视。响应 202 + 记录 id。

**自动验证**:
- 新表 `app_settings(key TEXT PRIMARY KEY, value TEXT NOT NULL)` + `app/services/settings_service.py`(`get_setting/set_setting`,值存 JSON);
- 开关 `verify_auto_enabled`(默认 `false`),`GET/PUT /api/v1/settings/verify` 暴露;
- 开启后由 `SchedulerService` 注册每周内部任务(cron 周一 03:30):遍历所有 `status="success"` 且(从未验证,或 `verified_at` 距今超过 30 天)的记录逐个入队 `verify_job`;每批完成后汇总 SystemLog,失败项走通知(见下)。

**通知**:验证失败复用现有渠道发送规则(`notify_on_failure` 语义),消息含记录 id、连接、库名、失败原因;成功不通知(避免噪音),仅在自动批量的 SystemLog 里体现。

**前端**:备份列表加"验证"按钮(已有文件且非 running 的行)+ 验证状态列(passed 绿/failed 红/未验证灰);设置页加"每周自动验证"开关;验证中经 `useJobStream` 显示进度。

## 5. 看门狗通知

**位置**:`SchedulerService` 注册每小时 IntervalTrigger 内部任务(`watchdog_check`,不受 `scheduler_enabled=false` 影响的逻辑:同样只在启用的进程内跑)。

**判定**(对每个 `enabled=True` 的 Schedule):
1. `last_success` = 该连接最近一条 `status="success"` 的 `started_at`;
2. 阈值 = 2 × cron 周期(用 `CronTrigger.from_crontab(expr)` 取当前时刻的下两次触发时间之差估算;估算失败(非法表达式)→ 跳过并记 SystemLog);
3. 无任何成功记录的连接:仅当 `DbConnection.created_at` 距今 > 48 小时才告警(新装宽限);
4. 告警去重:`app_settings` 存 `watchdog:<schedule_id>` = 上次告警时间,24 小时内不重复。

**通知**:新列 `NotificationConfig.notify_watchdog BOOLEAN NOT NULL DEFAULT 1`(设置页一个开关,默认开);内容含连接名、计划表达式、距上次成功时长;走邮件/企业微信既有发送函数。发不出的容错与备份通知一致(吞异常)。

**自愈语义**:发现告警条件消除(有新成功)后无需"恢复通知"(YAGNI);下一轮检查自然安静。

## 6. 安全与前端小项

1. **`/docs` 收紧**:`config.py` 增 `docs_enabled: bool = False`;`create_app` 中 `docs_url="/docs" if settings.docs_enabled else None`,`redoc_url=None`,`openapi_url` 同条件(前端不依赖 openapi.json);
2. **GZip 传输压缩**:`app.add_middleware(GZipMiddleware, minimum_size=1024)`(API 响应与 SPA 静态文件统一受益;实测 1.4MB 整包传输预计降至 ~450KB)。**更正说明**:前版设计写"echarts 按需引入"——实施核查发现 Dashboard 已是按需引入,500KB 是树摇后体积,故传输压缩替代该条;
3. **404 页**:新增 `views/NotFound.vue`,router 通配路由由 redirect 改为渲染 404 页(含回仪表盘链接);保留 `/login` 直通;
4. **状态标签抽取**:`frontend/src/composables/useStatusTag.ts`(状态→NTag 映射 + render 函数),History/Backups/Restore 三处消费。

## 9. 风险

| 风险 | 缓解 |
|---|---|
| 云删除误删(桶内 key 冲突/前缀配置错误) | key 即 `file_path` 与上传时完全一致;删除前校验 SyncTarget 属于该连接;测试覆盖 |
| 验证大文件内存占用 | 流式解压,常量内存 |
| cron 周期估算不准(复杂表达式如日历语义) | 用相邻两次 fire time 差值,天然适配任意表达式;解析失败跳过并记日志 |
| 看门狗误报(长任务/手动改表) | 2× 周期阈值 + 无成功记录 48h 宽限 + 24h 去重 |
| GZip 与 SSE 冲突 | StreamingResponse 不走 GZipMiddleware 缓冲(Starlette 对流式响应逐块处理,SSE 单条消息 < minimum_size 不受影响);E2E 覆盖 SSE 场景回归 |
