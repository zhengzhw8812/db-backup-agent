# v3.4.0 用户体验批量改进设计

日期:2026-11-01
来源:7 条用户反馈,逐条对到了现有代码。

## 背景与目标

用户试用后提出 7 条改进。目标:一次版本(3.4.0)内全部落地,保持 pytest 全绿、
`npm run build`(vue-tsc)通过、旧数据/旧路由平滑兼容。

**为什么**:当前 UI 有几处反直觉的点——填半天的表单弹窗一点遮罩就没了;
备份/历史/计划/恢复四页菜单割裂且两页表格高度重复;通知只支持每渠道一个账号;
版本号三处不一致(侧栏 v3.2.0 / 后端与 pyproject 3.0.0,功能实际已到 v3.3.1+)。

## 非目标

- 不做通知发送重试/发送历史/按渠道选择事件类型(全局三开关语义保持);
- 自备份只上传云端,不做从云端自动拉取还原;
- 不改认证、权限、任务队列架构;
- 移动端沿用现有 mcard 卡片模式,不重设计。

## 方案总览(含已否决的备选)

### 冺策 1:四页合一 —— 单页三 Tab(用户已选)

备选:(a) 只把恢复并入备份页,历史/计划独立 —— 两页重复表仍在,否决;
(b) 保持现状只加跳转 —— 菜单割裂问题不解决,否决。

- `/backups` 改为壳页面 + `n-tabs`:**备份文件 / 备份计划 / 恢复**;
- 壳页面 `views/Backups.vue` 持有共享状态(连接列表、备份文件、进行中任务、
  恢复记录、进度抽屉、轮询),三个 Tab 拆成组件
  `components/backup/FilesTab.vue`、`SchedulesTab.vue`、`RestoreTab.vue`;
- **备份文件表** = 现 Backups.vue 文件表 + History.vue 历史表合并:
  列:时间/连接/库/触发/状态/验证/大小/耗时/操作(下载|验证|恢复|删除),
  顶部连接名筛选框,分页 pageSize 15;移动端 mcard 同步补齐操作按钮;
- 文件表每行「恢复」→ 切到恢复 Tab 并预选该备份;
- 路由:Tab 状态进 URL query(`/backups?tab=files|schedules|restore`,缺省 files);
  `/schedules`→`/backups?tab=schedules`、`/history`→`/backups?tab=files`、
  `/restore`→`/backups?tab=restore` 做 redirect,书签落到对应 Tab 而非一律首页;
  侧栏菜单删 3 项;删除 `views/Schedules.vue`、`History.vue`、`Restore.vue`。

### 决策 2:通知改为渠道列表,支持同渠道多账号(用户已选)

备选:仅合并 UI 仍单套配置 —— 不解决多账号诉求,否决。

- **新表 `notification_channels`**:`id` / `type('email'|'wechat'|'feishu'|'serverchan')`
  / `name` / `enabled` / `config_json`(非敏感配置 JSON)/ `secret_enc`(该渠道敏感值
  JSON 整包 Fernet 加密)/ `created_at`;
  - 各类型字段:email→config{smtp_host,smtp_port,smtp_ssl,smtp_starttls,smtp_user,
    smtp_from,recipients} secret{password};wechat→config{corp_id,agent_id} secret{secret};
    feishu→config{} secret{webhook,sign};serverchan→config{} secret{sendkey};
- `notification_config` 表降级为**仅全局三开关**(notify_on_success/on_failure/watchdog),
  其余列停用不删(避免破坏性迁移);
- API:
  - `GET/PUT /settings/notifications` → 收窄为全局三开关(旧字段从响应移除,前端同仓更新);
  - `GET /settings/notification-channels`(列表,不含密钥明文)、
    `POST`、`PUT /{id}`(secret 留空不改)、`DELETE /{id}`、`POST /{id}/test`;
  - 旧 `POST /settings/notifications/test` 改为遍历所有启用渠道逐个测试;
- 发送路径重构 `notifications.py`:`_send_by_channel(db, crypto, ch, *, subject, content)`
  按 type 分派;`notify_backup_result` / `notify_generic` 改为:查全局开关 → 遍历启用渠道,
  逐渠道独立 try/except,返回 `[{channel_id,name,type,ok}]`;一个渠道失败不阻断其他;
- **数据迁移**(并入 `maintenance.migrate_schema`,幂等):以 `app_settings` 写入一次性标记
  `notification_channels_migrated`;标记存在则永不重跑 —— 避免用户删光渠道后重启被旧配置
  「复活」。标记不存在时,把旧 `notification_config` 中**已启用**的渠道各生成一行渠道记录
  (名称取「邮箱/企业微信/飞书/Server酱」;已填凭据但未启用的渠道不迁移,属用户主动关闭),
  旧表列停用不删、位不清零(保留回滚到旧版本的可用性);
- 前端 `Settings.vue` 通知卡片改为:全局三开关(独立保存)+ 渠道 `n-data-table`
  (类型标签/名称/启用 switch/操作:测试|编辑|删除)+「新建渠道」弹窗
  (类型下拉 → 动态字段,编辑时密钥留空不改)。渠道 CRUD 即时生效,
  移除原底部统一「保存设置」按钮对通知的绑定。

### 决策 3:表单弹窗防误关

- `Connections.vue`、`Schedules.vue`(并入 Tab 后同)、`CloudSync.vue` 两处表单弹窗,
  以及决策 2 新增的「新建/编辑渠道」弹窗(同样含大量凭据输入):
  `:mask-closable="false"` + `:close-on-esc="false"`;
- 恢复确认弹窗不改(无可丢失输入);右上角 X 与「取消」仍可关(显式操作)。

### 决策 4:计划「立即执行」

- 备份计划 Tab 行操作加「立即执行」:调现有 `POST /jobs/run`(按 connection_id),
  成功后切到「备份文件」Tab,复用进度抽屉与轮询逻辑。

### 决策 5:连接表单顺序与检测门控

- 字段顺序调整为:名称 → 类型 → 主机/端口 → **用户名 → 密码** → 数据库;
- 「检测」按钮在 主机+用户名+(密码或编辑态) 未满足时禁用(现为可点然后报错);
- blur 自动检测(800ms 防抖)保留。

### 决策 6:删除能力与自备份上云

- 备份历史删除:随合并文件表天然获得(现有 `DELETE /backups/{id}`);
- 自备份快照删除:新增 `DELETE /api/self-backup/{name}`(白名单 NAME_RE|SQL_RE;
  删本地文件,并尽力删除云端 `selfbackup/<name>` 副本);前端快照列表加删除按钮(popconfirm);
- 自备份上云:`sync_service` 新增 `upload_self_backup(db, crypto, path)` ——
  上传到**所有 enabled 的 CloudDestination**,对象 key `selfbackup/<文件名>`;
  单目标失败记 SystemLog(warning)不中断;
  - 调用点:`POST /self-backup/run`(gz 与 sql)及 `scheduler.self_backup_daily`(gz);
  - 设计取舍:同步上传不走 arq(配置库快照小),上传失败不影响自备份本身;
  - **云端轮转(用户已选)**:每次上传后清理云端 `selfbackup/` 前缀下超出 **30 份**的旧快照
    (仅匹配 `app-YYYYMMDD-HHMMSS.(db.gz|sql)` 白名单,按名字排序删除最旧;
    需给云适配器补「列举前缀下对象」能力,删除复用现有 delete;单目标清理失败记
    SystemLog(warning)不中断);
  - 设计取舍:目标集取「所有启用的云目标」而非同步规则 —— 自备份不属于任何连接;
    需排除某目标时在云存储页禁用即可。

### 决策 7:版本号统一 3.4.0

- `app/main.py` `version="3.4.0"`、`pyproject.toml` `3.4.0`、
  `AppLayout.vue` 侧栏 `v3.4.0`;README 更新日志补 v3.4.0 条目(本批 7 项);
  `/health` 自动跟随 app.version。

## 约束

- SQLite 无删列需求;新表靠 `create_all`,旧表补列靠 `maintenance._ensure_column`;
- 密钥继续 Fernet 加密、响应永不回传明文、留空不覆盖;
- 提交信息中文 `type(scope): 描述`;TDD,先写失败测试。

## 测试计划

- `test_maintenance`:旧通知配置 → 渠道迁移;迁移幂等;
- `test_notifications`:多渠道遍历、单渠道失败不阻断、按 type 分派;
- `test_settings_api`:渠道 CRUD/test 端点/全局开关收窄;
- `test_self_backup`:DELETE 白名单与存在性、`upload_self_backup` 成功与单目标失败继续;
- `test_spa`/`test_main_docs` 等引用旧路由处同步更新;前端 `npm run build` 通过。
