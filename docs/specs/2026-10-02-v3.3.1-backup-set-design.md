# v3.3.1 多库备份集(Backup Set)设计

- **日期**: 2026-10-02
- **状态**: 待审阅
- **前置**: 账号权限检测/库列举已上线(c04f747)。本批次让"多选库"产出**单一备份集**并可整体还原。

## 1. 备份集形态

勾选 ≥2 个库(手动或计划)→ **只建一条 BackupRecord**,记录新列 `db_names TEXT`(JSON 数组,实际备份的库);文件按类型:

| 类型 | 文件 | 内容 |
|---|---|---|
| pg | `pg_<cid>_<rid>.set.tar.gz` | `manifest.json`(库名/时间戳/各库校验和)+ 每库一个 `<db>.sql`(pg_dump 纯 SQL) |
| mysql | `mysql_<cid>_<rid>.set.sql.gz` | `mysqldump --databases …`(原生多库,自带 CREATE DATABASE)|
| mongo | `mongo_<cid>_<rid>.set.archive.gz` | `mongodump --archive --gzip --nsList=a,b`(原生多库)|

单库(≤1 个)行为与现状完全一致。校验和 = 归档文件字节的 SHA-256(与既有单文件语义一致)。进度 SSE 按库上报(`dump:app` 等)。

## 2. 还原语义

选该记录 + 目标连接 → 解包 → 按 manifest **顺序还原每库到同名数据库**:
- **pg**:目标库不存在则 `CREATE DATABASE`;逐库 `psql -d <db> -f <db>.sql`;部分库失败记录错误并继续,最终状态 `success`(全部成功)/`partial`(部分)/`failed`(全败)——`partial` 需 `error` 字段记录明细
- **mysql**:解压 → `mysql < dump.sql`(原生自动落回原库名)
- **mongo**:`mongorestore --archive --gzip --drop`(原生化整还原)

还原记录仍是一条 RestoreRecord;SSE 进度 `restore:app 2/3` 形式。

## 3. 触发面与兼容

- 手动(`POST /backups/run`)与计划调度:多库 → 集;单库 → 现状
- 云同步/保留策略/通知:零改动(一个文件一条记录)
- 历史多库多记录:不受影响,仍逐条还原
- 前端:备份列表对含 `db_names` 的记录显示"备份集(N 库)"徽标;Restore 页选中集后提示"将整集还原 N 个库"
- 已知限制:备份集不挑单库还原(整集语义);PG 逐库 dump 非同一时点(库间秒级差异)

## 4. 验证

- TDD:enqueue 多库→单记录;pg set 打包(manifest/每库文件/tar 结构);mysql set argv(--databases);mongo set argv(--nsList);restore 解包+create database+逐库 psql 顺序;partial 状态;校验和;SSE 进度

## 5. 不做(YAGNI)

集内挑库还原、跨连接备份集、增量、.db.gz 之外的集格式。
