# v3.4.2 六项问题修复设计

日期:2026-11-02。来源:用户部署 v3.4.1 后反馈 6 条,已逐条定位根因。
用户已拍板:APP_TZ 默认 Asia/Shanghai;全修并发版 3.4.2。

## 根因与修法

### 1+6 时区(显示差 8 小时 & cron 时区)

- **显示根因**:后端 `clock.utcnow()` 存 naive UTC,API 返回 ISO 无 `Z`;
  前端 `new Date("...T03:49")` 按浏览器本地(UTC+8)解析 → "8 小时前"。
- **cron 根因**:仓库 `docker-compose.yml` 未设 TZ,容器 UTC;APScheduler
  `CronTrigger` 默认本地时区 → cron 按 UTC 解释。
- **修法**:
  - 前端新增 `parseTs(iso)`:无时区标记补 `Z` 后再 `new Date`;全站
    `new Date(<iso>)` 调用点(useRelativeTime/SchedulesTab/Dashboard/Logs/
    Settings 等,grep 全量)统一替换 → 显示为浏览器本地时区。
  - 后端 `config` 新增 `app_tz`(env `APP_TZ`,默认 `Asia/Shanghai`);
    scheduler 内全部 `CronTrigger(...)` 显式传 `timezone=app_tz`
    (计划触发/每日自备份/周验证/watchdog 判定逻辑本身仍用 UTC 比较不变)。
  - `next_run_at` 计算后统一转 UTC naive 入库(与全库时间基准一致)。
  - `docker-compose.yml` 补 `TZ=Asia/Shanghai`;README/.env.example 补
    `APP_TZ` 说明(海外部署可覆盖)。

### 2 SSE 实时进度

- **根因(经 builder check 修正)**:初判"GZip 缓冲 SSE"已被证伪——镜像内
  Starlette 1.10.0 的 GZipMiddleware 默认排除 `text/event-stream` 且流式
  响应逐块 Z_SYNC_FLUSH,应用层不缓冲。真凶几乎可以锁定**反向代理缓冲**
  (nginx 系默认对 SSE 做 proxy_buffering,事件攒批直到超时/断开)。
- **修法**:SSE 响应(jobs/restore 两处 events)统一补
  `X-Accel-Buffering: no` + `Cache-Control: no-cache`(nginx 系反代识别
  后关闭缓冲);README 部署章节补反代配置指引(nginx 需
  `proxy_buffering off` 或依赖上述响应头;其他代理给对应说明)。
- **验证**:本地 Docker 起容器(直连,无反代)→ 建 SQLite 连接 → 登录取会话
  → 触发备份 → `curl -N` 观察 events 逐条实时到达(证明应用层健康,问题
  在部署侧);若用户反馈仍不实时,按其拓扑(反代类型)排查对应配置。

### 3+4 S3/云目标配置体验

- **现状确认**:行内"测试"仅保存后可用;无编辑端点/弹窗;错误透传 SDK 原文。
- **修法**:
  - `PUT /cloud-destinations/{id}`:全字段更新;`access_key`/`secret`/
    `mount_password` 空=不覆盖已存密文;**provider 不允许变更**(s3↔nfs
    属不同类型目标,改型请删除重建);nfs/smb 的 mount_config 变更时
    unmount→按新配置 mount,**重挂失败不回滚**:新配置保留入库,响应携带
    `mounted:false` 与 warning 提示(挂载是运行时状态,启动时 remount_all
    会重试;与 CREATE 的回滚策略不同,因为编辑有既有状态可退守)——
    (builder check 裁定项,实施时如发现与现状冲突再记录)。
  - `POST /cloud-destinations/test`(未保存测试):请求体即创建 payload,
    用临时凭据直测;nfs/smb 返回 400 提示"共享存储请保存后用列表探针"。
  - **错误分类指引**(`s3.py` test 包裹):连接超时/MaxRetry →
    "连不上:检查 Endpoint 格式(host:port,不带 https://)、网络/端口
    (MinIO 常用 9000)";NoSuchBucket → "桶不存在:检查桶名与 Region";
    AccessDenied/InvalidAccessKeyId/Signature → "认证失败:检查
    AccessKey/Secret";SSLError → "TLS 不匹配:检查 HTTPS 开关与端口"。
  - 前端:弹窗支持编辑(密钥留空不改,有提示);弹窗内"测试连接"按钮;
    表单补配置指引(placeholder 与说明文案)。

### 5 备份失败无系统日志

- **根因**:失败只写 `BackupRecord.error`,SystemLog 零记录,"日志"页只读
  SystemLog → 永远空。
- **修法**:`backup_service.run_backup` / `restore_service.run_restore` 终态
  failed → `SystemLog(error, source=backup/restore, message=连接名+库+失败,
  context=error 原文)`;cancelled → warning。既有 sync 的 warning 保留。
