# v3.2 存储扩展与通知扩展设计(NFS/SMB 目的地、飞书/Server酱通知、配置库自备份)

- **日期**: 2026-10-01
- **状态**: 待审阅
- **前置**: v3.1 批次已完成(`23aa7e7`,226 测试)。本批次在其上叠加。

## 1. NFS/SMB 备份目的地(容器内挂载)

**存储模型**(配置持久化 SQLite,随 `/data` 数据卷):
- `CloudDestination.provider` 取值扩展 `nfs`/`smb`;
- 新列 `mount_config TEXT`(JSON,非密字段):nfs → `{"server","export","version":"nfs4|nfs3"}`;smb → `{"server","share","domain?","username?"}`;
- 新列 `mount_password_enc TEXT`(SMB 密码,Fernet 加密;NFS 置空);
- 挂载点约定:容器内 `/mnt/dest-<id>`(容器本地路径,重建容器后由启动重挂恢复)。

**挂载服务**(`app/services/mount_service.py`,全部经 subprocess 调用系统 mount/umount):
- `mount_destination(dest, crypto)`:已挂载(`os.path.ismount`)则幂等跳过;SMB 凭据经 `/run/dest-<id>.creds`(0600,`credentials=` 引用,挂载后即删)传递,不进命令行;NFS 默认 `-t nfs4 vers=4.1`,version=nfs3 时 `-t nfs vers=3,nolock`;SMB `-t cifs vers=3.0`;
- `unmount_destination(dest_id)`:lazy umount + 清理挂载点目录;
- `remount_all(db, crypto)`:lifespan 启动时对全部启用的 nfs/smb 目的地逐个挂载,单目的地失败记 SystemLog(error)后继续;
- 禁用/删除目的地时卸载。

**存储适配器**(`app/cloud/shares.py`):`ShareStorageAdapter` 注册为 `nfs`/`smb` 两个 provider,行为一致——`test`=挂载点探测(mountpoint 检查 + 写读探针文件);`upload`=按 key 落文件到挂载点(含 `prefix` 子目录,`mkdir parents`);`delete`=unlink。**SyncTarget、备份后同步、保留清理云联动全部零改动复用**。

**路由接线**(`app/routers/cloud.py`):创建/更新 nfs/smb 目的地 → 立即挂载(失败 400 + stderr);test 端点重构为按 provider 构建配置(现硬编码 S3 CloudConfig);删除/禁用 → 卸载。

**镜像与部署**(容器内挂载的既定代价):Dockerfile 增 `nfs-common`、`cifs-utils`;`docker-compose.yml` 增 `privileged: true`(附安全说明注释);README 部署节同步。

## 2. 飞书 + 个人微信(Server酱)通知

- `NotificationConfig` 新列(走 `_ensure_column`):`feishu_enabled BOOL`、`feishu_webhook_enc TEXT`(webhook URL 含 token,加密、只写不回显)、`feishu_secret_enc TEXT`(可选加签)、`serverchan_enabled BOOL`、`serverchan_sendkey_enc TEXT`;
- `notifications.py` 新增 `_send_feishu`(POST webhook,`{"msg_type":"text","content":{"text":...}}`;有加签密钥时顶层附 `timestamp` + HMAC-SHA256(base64)`sign`)与 `_send_serverchan`(POST `https://sctapi.ftqq.com/<key>.send`,`title`+`desp`);两者接入 `notify_backup_result`(成功/失败)与 `notify_generic`(失联告警)渠道循环,独立 try/except,受既有 `notify_on_success/on_failure/watchdog` 开关约束;
- **新增通知测试端点** `POST /api/v1/settings/notifications/test`:对所有已启用渠道各发一条"[测试]"消息,返回逐渠道结果 `{"email":..,"wechat":..,"feishu":..,"serverchan":..}`(未启用 → null);全部失败 → 400;
- 企业微信/邮件保持不变。

## 3. 配置库本地自备份

- `app/services/self_backup.py::run_self_backup(data_dir, keep=7)`:对 `data/sqlite/app.db` 执行 `VACUUM INTO` 临时快照(在线一致性,规避 WAL)→ gzip 压缩为 `data/selfbackup/app-<YYYYMMDD-HHMMSS>.db.gz` → 保留最新 7 份、超出删除 → 写 SystemLog(info/error);
- 调度:SchedulerService 内部 cron 每日 04:00(`id="self_backup_daily"`),失败不阻塞其余任务;
- API(新 `app/routers/self_backup.py`,挂 `/api/v1`):`POST /self-backup/run`(202/同步返回快照名)、`GET /self-backup`(列表:name/size/created_at)、`GET /self-backup/{name}/download`(`name` 白名单正则 `^app-\d{8}-\d{6}\.db\.gz$` 防穿越);
- 恢复:下载 + 文档化手动替换(停容器 → 覆盖 `data/sqlite/app.db` → 起容器);不做在线自动恢复;
- 前端:Settings 页"配置库自备份"卡片(立即备份、快照列表、下载)。

## 4. 前端

- **CloudSync.vue**:目的地表单按 `provider` 动态渲染(s3 现有字段 / nfs:server+export+版本 / smb:server+share+域+账号+密码);表格类型列显示 nfs/smb;操作列对 nfs/smb 显示挂载状态(经 test 端点探测或列表接口返回 `mounted` 布尔);
- **Settings.vue**:飞书(Server酱)字段 + "发送测试通知"按钮(展示逐渠道结果);配置库自备份卡片;
- `frontend/src/api/cloud.ts`、`settings.ts`、新增 `self-backup.ts` 对应接口。

## 5. 验证

- 单元:ShareStorageAdapter(test/upload/delete 用真实临时目录);mount_service(mockerpatch subprocess 断言 mount 参数/凭据文件内容与权限/umount/幂等跳过);飞书消息体与加签(SignatureHMAC 断言)、Server酱请求体;自备份(VACUUM INTO 真库、保留轮转、name 正则防穿越);
- E2E(privileged 容器):先 `mount -t tmpfs tmpfs /mnt/dest-1` → 创建 nfs 目的地(挂载服务检测已挂载幂等跳过)→ 目的地测试探针 → 备份+同步落"盘"(宿主读 tmpfs 文件核对)→ 保留联动删除;飞书 webhook 指向宿主 HTTP 桩,触发备份断言收到 `msg_type=text`;自备份 run → 文件生成 + 下载;`/docs` 无暴露回归;
- 已知限制:真实 NFS/SMB 服务端交互不在验证范围(需外部服务器);Server酱出站为硬编码 https,仅单测;
- 全量:pytest ≥226+新增、前端构建、docker build、CI 绿。

## 6. 不做(YAGNI)

NFS Kerberos、AD 域控 SMB、自动重挂监控循环(启动重挂 + 状态徽标 + SystemLog 已覆盖)、FTP/WebDAV、自备份在线热恢复、快照加密。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| privileged 扩大攻击面 | 仅挂载用途;文档注明;密钥/凭据仍 Fernet 加密;SMB 凭据文件 0600 用后即删 |
| 挂载点残留(容器重建) | `/mnt` 为容器层,重启即清;启动重挂幂等 |
| VACUUM INTO 与业务并发 | SQLite WAL 下 VACUUM INTO 取一致性快照;失败仅丢一次自备份 |
| webhook/SendKey 泄露到前端 | 只写不回显(沿用密码字段模式),GET 返回 null |
