# v3.2 存储扩展与通知扩展 — 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans(Native)。步骤用 `- [ ]` 勾选。

**Goal:** NFS/SMB 目的地(容器内挂载)、飞书+Server酱通知、通知测试端点、配置库自备份。

**Architecture:** 挂载经 mount_service(subprocess)+ ShareStorageAdapter(落盘到挂载点),复用 SyncTarget/同步/保留管线;新通知渠道接入 notify_backup_result/notify_generic 分发;自备份 VACUUM INTO + 保留 7 份。

**Spec:** docs/specs/2026-10-01-v3.2-shares-notify-selfbackup-design.md(绑定权威)。

## Global Constraints

- 既有 226 测试不改断言全绿;TDD 先红后绿;每任务一提交;
- 凭据(SMB 密码/飞书 webhook/加签密钥/SendKey)一律 Fernet 加密、只写不回显;
- 挂载幂等(ismount 跳过);单目的地失败不拖垮其余(启动重挂/看门狗同风格);
- name 白名单正则防穿越;SMB 凭据文件 0600 用后即删。

## Review Focus

1. SMB 密码不得出现在命令行/日志 — T1 测试 pin(断言 argv 与 creds 文件);
2. 挂载幂等:已挂载目的地重复挂载必须跳过 — T1 测试 pin;
3. 下载 name 穿越(`/etc/passwd`、`../`)必须 404 — T5 测试 pin;
4. webhook/SendKey 不回显到 GET 响应 — T3 测试 pin;
5. 自备份失败不留半截文件、不影响主流程 — T5 测试 pin。
